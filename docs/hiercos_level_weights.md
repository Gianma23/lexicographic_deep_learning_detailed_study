# Principled Level Weights for Hier-COS

Working note for the supervisor discussion on `model.weight_mode`.
All numbers below are computed from this repository's code and from the actual
training splits of the three datasets (script output reproduced in the tables).

---

## 1. What the current weights are

The Hier-COS level weights are produced in
[topology.py:123-126](../models/orthonormal_plugin/topology.py#L123-L126):

```python
level_weights = torch.arange(depth, 0, -1, dtype=torch.float32)   # [h, h-1, ..., 1]
level_weights = torch.exp(1.0 / level_weights)                    # exp(1/(h+1-l))
level_weights = level_weights / torch.norm(level_weights, p=2)    # L2 normalise
level_weights = level_weights.pow(2)                              # square -> sums to 1
```

Writing `h = depth` and using the paper's 1-based level index `l = 1..h`, the entry of
`torch.arange(h, 0, -1)` at level `l` is `h + 1 - l`, so the exponential term is exactly
the paper's `exp(1/(h+1-l))`.

`weight_mode: kl_leaf` uses this vector, `kl_coarse` reverses it, `equal` replaces it
with `1/h`.

For `h = 3` this yields, coarse -> fine:

| mode | coarse | mid | fine |
|---|---|---|---|
| `kl_leaf` (default in all three presets) | 0.162 | 0.225 | 0.613 |
| `kl_coarse` | 0.613 | 0.225 | 0.162 |
| `equal` | 0.333 | 0.333 | 0.333 |

### The normalisation step doubles the exponent

L2-normalising and then squaring is algebraically identical to L1-normalising the squares,
so the implemented weight has the closed form

```
w_l  =  exp(1/(h+1-l))^2 / sum_k exp(1/(h+1-k))^2  =  softmax_l( 2 / (h+1-l) )
```

The `.pow(2)` therefore acts as an inverse temperature on the weight distribution, and the
implemented weights correspond to `exp(2/(h+1-l))`, not to `exp(1/(h+1-l))`:

| `h = 3` | coarse | mid | fine |
|---|---|---|---|
| repo code, i.e. `softmax(2/(h+1-l))` | **0.162** | 0.225 | **0.613** |
| plain normalised `exp(1/(h+1-l))`, i.e. `softmax(1/(h+1-l))` | 0.242 | 0.286 | **0.472** |

The gap widens with depth: at `h = 5` the leaf weight is 0.486 under the implemented form
against 0.329 under plain normalisation.

### Resolved against the paper and the released code

**The squaring comes from the authors' own code, and this repository reproduces it
faithfully.** Upstream
[`util/hiercos_construction.py:243-244`](https://github.com/Depanshu-Sani/Hier-COS/blob/122b01dff393d3b562ad2daac494496fda65131c/util/hiercos_construction.py#L243-L244)
(commit `122b01d`, the version pinned in
[model_repo_differences.md](model_repo_differences.md)):

```python
arr = np.arange(len(class_hierarchy_labels), 0, -1)  # 5 4 3 2 1
node_prob_distribution.append(np.square(np.exp(1 / arr) / np.linalg.norm(np.exp(1 / arr))).tolist())
```

This is line-for-line equivalent to [topology.py:123-126](../models/orthonormal_plugin/topology.py#L123-L126).
Upstream uses it at `hiercos_construction.py:329` to build the KL target `l_gt`, the same
role `_build_node_targets` plays here. So there is no local divergence.

**The paper text, however, states only a plain normalisation.** Hier-COS (Sani & Anand,
CVPR 2026; arXiv:2503.07853), Section 3.4:

> The weights `w_l` for `l ∈ [h]` are generated by the function `w_l = exp(1/(h+1-l))`.
> [...] **The target distribution `P` is then obtained by normalizing the weight vector `w`.**

Normalising `w` to obtain a distribution reads as `P_l = w_l / sum_k w_k`. The code
normalises `w^2`, not `w`. Squaring an L2-normalised vector does yield a valid
distribution, so this is not a contradiction — but it is an extra step that the equation
does not contain, and it changes the numbers materially:

| `h = 3` | coarse | mid | fine |
|---|---|---|---|
| paper equation as written, `P ∝ w_l` | 0.242 | 0.286 | 0.472 |
| released code and this repo, `P ∝ w_l^2` | 0.162 | 0.225 | **0.613** |

**The paper's stated justification does not narrow the choice.** The same section gives
three desiderata and nothing more:

> This exponential mapping ensures the sequence is strictly monotonically increasing and
> exhibits a heavy-tailed characteristic, where the influence of the terminal weights
> (`w_h`) is amplified. Crucially, the calculation of `w_l` involves an exponent that
> remains positive and bounded (`1/h <= 1/(h+1-l) <= 1`), which is deliberately designed to
> maintain numerical stability.

So the requirements are: (i) monotonically increasing root -> leaf, (ii) heavy-tailed /
leaf-amplifying, (iii) bounded exponent for numerical stability. An infinite family of
functions satisfies all three — including `w_l ∝ C_l` and `w_l ∝ H(Y_l)` proposed below.
**None of the three desiderata references the hierarchy's shape**, which is exactly why the
resulting vector is dataset-independent. The squaring in the code amplifies desideratum
(ii) further, which suggests it may be deliberate, but it is undocumented either way.

This strengthens rather than weakens the objection: the weighting is under-determined at
two separate points — the choice of monotone function, and the choice of normalisation.

### Why this is hard to defend

1. **No stated principle.** `exp(1/(h+1-l))`, an L2 normalisation, and a squaring step are
   three composed transforms with no derivation. Replacing `exp` by any other increasing
   function, or dropping the squaring, changes the answer with equal justification — and as
   shown above, dropping the squaring alone moves the leaf weight from 0.613 to 0.472.
2. **The weights never look at the hierarchy.** They depend only on `h`. The vector
   is *bit-for-bit identical* for CIFAR-100 (8/20/100), CUB-200 (13/38/200) and
   FGVC-Aircraft (30/70/100) — three hierarchies with very different shapes. A weighting
   that claims to balance levels but never reads the level sizes cannot be balancing
   anything dataset-specific.
3. **It is not even monotone in the property it seems to target.** On Aircraft the fine
   level is only 100/70 ≈ 1.43x the mid level, but the weight ratio is still the fixed
   0.613/0.225 ≈ 2.7x inherited from the formula.

Point 2 is the argument I would lead with: it is checkable in one line and it is exactly
the professor's objection made concrete.

## 2. What the weight actually controls (this differs by loss mode)

This matters, because "put the losses on the same scale" is only literally meaningful in
one of the three modes.

| `model.loss` | softmax scope | role of `w` |
|---|---|---|
| `level_softmax_ce_reg` | per level, over `C_l` nodes | **true per-level loss scale.** `w_l` multiplies an independent CE whose chance value is `log C_l`. |
| `global_softmax_ce_reg` | one softmax over `N = sum_l C_l` nodes | chance CE is `log N` for *every* level, so levels start on the same scale by construction. `w` sets the **equilibrium probability allocation** across the path: the per-level CE floor is `-log w_l`. |
| `kl_reg` (paper-faithful, current default) | one softmax over `N` nodes | `w` **is the target distribution** over the `L` path nodes (see `_build_node_targets`, [losses.py:202-225](../models/orthonormal_plugin/losses.py#L202-L225)). It is not a loss scale at all. |

In all three modes the KL/CE gradient on the level-`l` correct node scales with `w_l`, so
`w` always controls relative per-level gradient pull. But the *derivation* of a good `w`
should follow the mode:

- `level_softmax_ce_reg` -> scale-equalisation arguments (Section 5) are exact.
- `global_softmax_ce_reg` / `kl_reg` -> the right question is **"what is the correct
  target mass allocation over the path?"**, not "what makes the losses equal".

---

## 3. Proposed framework: separate *what you optimise* from *numerical conditioning*

I propose presenting the weight as a product of two factors, each independently derivable
and neither tuned:

```
w_l  =  m_l  *  s_l
       ^^^^     ^^^^
       metric   scale
       coeff.   normaliser
```

- `m_l` — read off the **evaluation metric** the model is selected on. Zero free
  parameters.
- `s_l` — makes the per-level *surrogate* comparable. Only non-trivial for
  `level_softmax_ce_reg`; equals 1 for the global-softmax modes.

This reframes the question from "which weights work best" (empirical, what the professor
objected to) to "which objective are we optimising" (a modelling decision that must be
declared anyway).

---

## 4. Metric-derived coefficients `m_l` — three exact derivations

All three of this repo's headline metrics ([metrics.py](../train/metrics.py)) yield a
weight vector by direct algebra. Write `err_l = 1[y-hat_l != y_l]`.

### 4a. Weighted AP -> `m_l ∝ C_l`  (exact identity)

`weighted_average_precision` is literally class-count-weighted per-level accuracy
([metrics.py:101-123](../train/metrics.py#L101-L123), `weight = float(logits.size(-1))`):

```
1 - wAP  =  ( sum_l  C_l * E[err_l] )  /  sum_l C_l
```

This is an identity, not a bound. **If wAP is the reported metric, the training weights
that match it are `w_l ∝ C_l`, and any other choice trains a different objective than the
one being reported.**

This coefficient has an independent second derivation for the global-softmax / KL modes.
Under a uniform within-level marginal, the expected target mass placed on a node `u` at
level `l` is `w_l / C_l`. Requiring that expectation to be equal for **all** `N` nodes of
the global softmax — the non-informative prior over the node set — gives `w_l / C_l =
1/N`, i.e. `w_l = C_l / N`. Two unrelated routes to the same vector is the strongest
evidence available here that it is the natural choice.

### 4b. Full-path accuracy -> `m_l ∝ 1`  (union bound)

```
1 - FPA  =  P( exists l : err_l )  <=  sum_l  E[err_l]
```

All coefficients are 1. **FPA-aligned weighting is exactly `equal`** — which gives
`weight_mode: equal` a foundation it currently lacks.

### 4c. AHD -> `m_l ∝ (L - l)`  (union bound)

`average_hierarchical_distance` is `depth` minus the shared prefix length
([metrics.py:155-160](../train/metrics.py#L155-L160)), i.e. the number of levels whose
*prefix* is wrong:

```
AHD  =  sum_{l=0}^{L-1} 1[ exists k <= l : err_k ]
     <= sum_{k=0}^{L-1} (L - k) * err_k
```

A level-`k` error corrupts every prefix from `k` to `L-1`, so it is counted `L-k` times.
For `L = 3` this gives `[3, 2, 1] / 6 = [0.500, 0.333, 0.167]` — **coarse-heavy, and
derived rather than assumed.** This is the principled version of what `kl_coarse` gestures
at.

### Surrogate step is also a bound

Replacing `err_l` by cross-entropy is rigorous: if the level-`l` prediction is wrong then
the target probability is at most 1/2, so `err_l <= CE_l / log 2`. The constant is common
to all levels and therefore does not change the relative weights. This bound holds exactly
for `level_softmax_ce_reg` (per-level normalised probabilities) and only approximately for
the global-softmax modes, where the level probabilities are not renormalised within level.

## 5. Scale normalisers `s_l`

Only for `level_softmax_ce_reg`, where each level has its own softmax.

- **`s_l = 1 / log C_l`** — at initialisation a uniform predictor gives `CE_l = log C_l`,
  so this makes every weighted level term equal 1 nat at step 0. This is the direct,
  defensible reading of "put the losses on the same scale".
- **`s_l = 1 / H(Y_l)`** — same idea using the *empirical* train marginal entropy instead
  of `log C_l`. `H(Y_l)` is the CE of the best prior-only predictor, so this equalises
  "distance from the trivial baseline" rather than "distance from chance". It matters when
  levels are imbalanced: on CUB the order level has `C = 13` but only `exp(H) = 3.9`
  effective classes.

Measured values (this repo's train splits):

| dataset | level | `C_l` | `log C_l` | `H(Y_l)` | `exp(H)` |
|---|---|---|---|---|---|
| CIFAR-100 | coarse1 / coarse2 / fine | 8 / 20 / 100 | 2.079 / 2.996 / 4.605 | 1.987 / 2.996 / 4.605 | 7.3 / 20.0 / 100.0 |
| CUB-200 | order / family / species | 13 / 38 / 200 | 2.565 / 3.638 / 5.298 | 1.362 / 3.152 / 5.298 | 3.9 / 23.4 / 200.0 |
| Aircraft | manufacturer / family / variant | 30 / 70 / 100 | 3.401 / 4.248 / 4.605 | 2.888 / 4.068 / 4.605 | 18.0 / 58.5 / 100.0 |

CUB is the informative case: 13 orders, but the label distribution is so skewed that the
level carries only 1.36 nats. A weighting built on `C_l` alone treats CUB orders as ~3.4x
harder than they empirically are.

## 7. On the "ratio between number of classes" idea

This hint is right in spirit but needs one correction to work. Let `b_l = C_l / C_{l-1}`
be the branching factor.

**Raw ratio `w_l ∝ b_l` fails**, because the root level has no parent so `b_0 = C_0`
dominates:

| dataset | `b` | normalised `w` |
|---|---|---|
| CIFAR-100 | [8, 2.50, 5.00] | [0.516, 0.161, 0.323] |
| CUB-200 | [13, 2.92, 5.26] | [0.614, 0.138, 0.248] |
| Aircraft | [30, 2.33, 1.43] | **[0.889, 0.069, 0.042]** |

The Aircraft row is degenerate — 89% of the weight on manufacturers.

**The log ratio is the principled form.** `log b_l = log C_l - log C_{l-1}` is exactly the
conditional entropy `H(Y_l | Y_{l-1})` under uniform marginals, and because the hierarchy
is a tree (each `Y_{l-1}` is a deterministic function of `Y_l`) the chain rule holds
exactly:

```
H(Y_L)  =  H(Y_0) + H(Y_1 | Y_0) + ... + H(Y_{L-1} | Y_{L-2})
```

So `w_l ∝ H(Y_l | Y_{l-1})` splits the total leaf-label information into the amount each
level actually *adds* — the weighted sum is a decomposition of the leaf objective rather
than an arbitrary mixture. This is the defensible version of the professor's third bullet.

Empirically it is still uncomfortable on Aircraft ([0.627, 0.256, 0.117] using empirical
conditional entropies, [0.739, 0.184, 0.077] using `log b_l`), because Aircraft's variant
level adds very little information beyond family. That is arguably *correct* behaviour,
but it is a large departure from every published Aircraft setting and I would present it
as an interesting diagnostic rather than as the headline proposal.

## 8. Finding: the regulariser already imposes an unchosen `sqrt(C_l)` weighting

This is worth raising independently of the weight question.

In every loss mode the level regulariser is summed **unweighted** and `weight_mode` never
touches it ([losses.py:228-252](../models/orthonormal_plugin/losses.py#L228-L252),
[losses.py:456-461](../models/orthonormal_plugin/losses.py#L456-L461)). The term is an
L1 distance between a one-hot vector and an L2-normalised non-negative vector of length
`C_l`, whose value at initialisation grows like `sqrt(C_l)`.

This is not a repository artefact: the paper's Eq. (4) defines `L_reg` as an unweighted sum
over levels of `|| delta_l - P_E(l) x / ||P_E(l) x|| ||_1`, and the total loss is
`L_total = L_kl + alpha * L_reg`. The weights `w` enter only `L_kl`. So the observation
below applies to the published method, not only to this implementation.

Measured at random initialisation (4096 samples per level):

| dataset | reg per level | implicit share | current `kl_leaf` |
|---|---|---|---|
| CIFAR-100 | 2.74 / 4.25 / 8.84 | 0.173 / 0.268 / 0.558 | 0.162 / 0.225 / 0.613 |
| CUB-200 | 3.49 / 5.69 / 12.18 | 0.163 / 0.266 / 0.571 | 0.162 / 0.225 / 0.613 |
| Aircraft | 5.11 / 7.51 / 8.84 | 0.238 / 0.350 / 0.412 | 0.162 / 0.225 / 0.613 |

**Observation.** The regulariser's implicit leaf-heavy weighting is close to the current
`kl_leaf` vector on CIFAR and CUB. With `alpha = 0.15` on CUB the regulariser is roughly
37% of the objective at initialisation (`alpha * sum(reg) = 3.20` against a global CE of
`log N = 5.53`); on Aircraft with `alpha = 0.10` it is roughly 29%.

**Interpretation.** Changing `weight_mode` currently reweights only part of the objective;
a substantial `sqrt(C_l)`-shaped leaf-heavy pull survives untouched. Any weighting study
should either (a) apply `w` to the regulariser as well, or (b) normalise the regulariser
per level by `sqrt(C_l)`, and state which was chosen. Otherwise a "coarse-heavy" run is
not actually coarse-heavy.

*Caveat:* this is an initialisation-time measurement on random logits, not a measurement
during training. The honest claim is that the objective contains an unchosen level-dependent
scale, not that it dominates throughout training.

## 9. Weight-free alternatives (strongest answer to "empirical without foundation")

### 9a. Homoscedastic uncertainty weighting
Kendall, Gal & Cipolla, *Multi-Task Learning Using Uncertainty to Weigh Losses for Scene
Geometry and Semantics*, CVPR 2018. Learn one scalar `sigma_l` per level and optimise
`sum_l (1/sigma_l^2) * L_l + sum_l log sigma_l`. The weights become maximum-likelihood
estimates under a per-level noise model instead of hand-set constants. Cost: 3 extra
scalar parameters; risk: `sigma` can drift and the balance becomes non-stationary.

### 9b. Gradient-norm equalisation as a *check*, not a method
"Same scale" is more honestly a statement about gradients than about loss values. This
repo already logs per-level gradient diagnostics
([trunk_metrics.py](../train/trunk_metrics.py), glossary in
[GRADIENT_PARAM_DIAGNOSTIC_LOGS.md](GRADIENT_PARAM_DIAGNOSTIC_LOGS.md)). Running one
`equal`-weighted job and reading off the per-level trunk gradient norms turns a
theoretical claim into a measurement: it says whether `1/log C_l` actually equalises
gradient scale on these hierarchies, or whether it over/under-corrects.

This is the cheapest way to make the proposal empirically grounded rather than only
analytically motivated.

### 9c. Do not scalarise at all — the thesis-native answer
Any fixed `w` is a *linear scalarisation* of a genuinely multi-objective problem, and no
scalarisation is neutral. The repository's own lexicographic path
(`train.lexicographic.enabled`, supported for Hier-COS with `global_softmax_ce_reg` or
`level_softmax_ce_reg`, see [train/lexicographic/config.py:157-163](../train/lexicographic/config.py#L157-L163))
replaces the magnitude question with a *priority* question: coarse before fine, resolved by
gradient projection rather than by a coefficient.

Framed this way the weight-choice problem is not a nuisance to be tuned away — it is the
motivation for the lexicographic formulation. I would use this as the closing argument:
the reason the Hier-COS weights are unfounded is that scalarised hierarchical losses have
no canonical weights, which is precisely the gap the lexicographic method addresses.

## 10. Recommendation

1. **Headline proposal: `w_l ∝ C_l` (W2), justified as metric-aligned.** It is an exact
   identity with the reported wAP, it has a second independent derivation as the uniform
   node prior under the global softmax, it is the professor's "number of classes per level"
   hint in its cleanest form, and it has zero tunable parameters.
2. **Report `equal` (W1) as the FPA-aligned choice and `∝ (L-l)` (W3) as the AHD-aligned
   choice**, so the thesis states one weight vector per metric rather than one universal
   vector. This directly converts "empirical" into "declared objective".
3. **Use `∝ H(Y_l)` (W5) as the principled drop-in for the current leaf-heavy default**
   if continuity with the existing results matters.
4. **Add `1/log C_l` scale normalisation only for `level_softmax_ce_reg`**, and say
   explicitly that it does not apply to `kl_reg` / `global_softmax_ce_reg` because those
   share one softmax.
5. **Fix or document the regulariser's implicit `sqrt(C_l)` weighting** before running the
   comparison, otherwise the study measures a confounded objective.

## 11. Proposed experiments

Isolating one variable — the level weight vector — on the existing presets:

- Fixed: `model.loss: kl_reg` (paper-faithful), backbone, `alpha`, optimiser, schedule,
  seed, split.
- Varied: `w ∈ {current kl_leaf, equal, ∝C_l, ∝(L-l), ∝H(Y_l)}`.
- Datasets: CIFAR-100 and Aircraft first (Aircraft has the flattest hierarchy and
  separates the schemes most), CUB-200 third.
- Report FPA, wAP, AHD, TICE under both top-down and independent decoding, each from the
  checkpoint selected for that decoding mode.
- Pre-registered prediction to test the framework rather than fit it: `∝ C_l` should win
  on wAP, `∝ (L-l)` should win on AHD, `equal` should be competitive on FPA. If the
  metric-aligned weights do *not* win their own metric, the scalarisation is too loose to
  control the metric — which is itself a publishable observation and a direct argument for
  the lexicographic route.

A secondary ablation with `level_softmax_ce_reg` would test whether the `1/log C_l`
normaliser matters once the softmax is per-level.

## 12. Limitations to state

- Sections 4a-4c bound the **0-1 error**, not the CE surrogate, and the CE bound
  (`err <= CE/log 2`) is exact only under per-level softmax. Under `kl_reg` and
  `global_softmax_ce_reg` the link between `w` and the metric is motivated, not proved.
- Section 8 measures the regulariser at initialisation only.
- `H(Y_l)` is estimated on the training split and inherits its class imbalance; on CUB the
  split is small (5194 train images) so the order-level entropy estimate is the least
  stable of the nine.
- No claim is made that any of these weightings improves absolute accuracy. The claim is
  that each is *derivable*, which the current `exp(1/(h+1-l))` vector is not.
- Section 1's paper-vs-code discrepancy is a reading of the sentence "the target
  distribution `P` is then obtained by normalizing the weight vector `w`". The paper does
  not define "normalizing" formally, so it is possible the authors intended the
  unit-norm-then-square construction. The safe claim is that the equation as printed does
  not produce the numbers the released code produces.
- **`w_l ∝ (L-l)` (W3) contradicts the method's design rationale.** The paper motivates
  monotonically *increasing* weights in order to "promote high leaf-level discrimination";
  a coarse-heavy vector inverts that. W3 should therefore be presented as an
  AHD-aligned diagnostic that tests whether the architecture's leaf bias is load-bearing,
  not as a drop-in default.
