# HCC Internal Insights

This note summarizes what the HCC diagnostics are saying across CIFAR-100, CUB-200, and FGVC-Aircraft, with emphasis on why `FPA_independent` improves on CIFAR but degrades badly on CUB and Aircraft.

For the raw metric glossary, see [HCC_DIAGNOSTIC_LOGS.md](HCC_DIAGNOSTIC_LOGS.md). This file focuses on interpretation.

## Scope

The most reliable source for the hard-switch story is the validation `run_log.jsonl` in the `step100` runs:

- `hcast_hcc_cifar100_step_100epochs`
- `hcast_hcc_cub200_step_100epochs`
- `hcast_hcc_aircraft_step_100epochs`

Why validation logs and not only `test_metrics.yaml`:

- In the `step100` runs, HCC is off through epoch 100 and switches to full hard projection at epoch 101 because `alpha_start_epoch=100` and `alpha_schedule=step`.
- `test_metrics.yaml` stores the best checkpoint, which can be from before the switch.
- For the switch analysis, use epoch 100, epoch 101, and epoch 115 from `run_log.jsonl`.

## Executive Summary

HCC changes the model in two ways:

- It changes evaluation, because metrics use `effective_probs_per_level` when HCC is active.
- It changes training, because the loss also uses those probability scores instead of raw logits.

That happens in:

- [models/hcast/model.py](../models/hcast/model.py)
- [models/hcast/losses.py](../models/hcast/losses.py)
- [train/eval.py](../train/eval.py)

The key internal behavior is:

1. The projector enforces hierarchical sum constraints.
2. The renormalization step reallocates child probabilities so each parent subtree sums exactly to the parent probability budget.
3. This mostly reweights entire parent subtrees, not sibling order inside a parent.

That third point is why the within-parent rank metric barely changes in the logs, while the global independent fine argmax can still collapse.

## How HCC Works Internally

The projector enforces:

- `p1 = M12 @ p2`
- `p2 = M23 @ p3`

The relevant code is in [models/hcast/hard_hierarchy.py](../models/hcast/hard_hierarchy.py).

The most important part is the simplex stabilization:

- `p1` is kept fixed.
- `p2` is renormalized so each middle subtree sums to `p1`.
- `p3` is renormalized so each fine subtree sums to `p2`.

Conceptually, after HCC the fine score behaves like:

`post_leaf_prob ~= parent_budget(parent) * within_parent_share(leaf | parent)`

This is the central reason for the dataset differences:

- If subtree sizes are uniform, the rescaling is relatively benign.
- If subtree sizes are uneven, small parents can concentrate their budget into one or two leaves, while large parents must spread it across many siblings.
- Independent fine decoding uses a global argmax across all leaves, so it is sensitive to this imbalance.
- Top-down decoding is less affected because it picks the parent first and only then picks the leaf inside that parent.

## The Metric Reading Pattern That Matters Most

The most informative diagnostic combination is:

- `support_l1_ind_correct`
- `acc_l2_ind_given_l1_correct`
- `acc_l2_td_given_l1_correct`

These metrics answer a very specific question:

- "When the parent prediction is correct, can the decoder still recover the correct leaf?"

The condition is applied separately for each decoder:

- `acc_l2_ind_given_l1_correct` uses the subset where the independent `L1` prediction is correct.
- `acc_l2_td_given_l1_correct` uses the subset where the top-down `L1` prediction is correct.

So these two accuracies are not necessarily computed on the same samples.

That is why the right reading order is:

1. Check `support_l1_ind_correct` and `support_l1_td_correct` first.
2. Then read the conditional accuracies.
3. Only after that compare independent and top-down.

What each metric is isolating:

- `support_l1_*_correct` tells you how often the decoder even reaches the correct parent.
- `acc_l2_*_given_l1_correct` removes the parent mistake from the analysis and tests only the leaf decision on the "parent already correct" subset.

This gives a clean decomposition:

- low support means the decoder is often failing at the parent level.
- low conditional leaf accuracy means that even after getting the parent right, the decoder still fails at the leaf level.

Practical reading:

- If `support_l1_ind_correct` stays high, the parent prediction is still mostly right under independent decoding.
- If `acc_l2_td_given_l1_correct` stays high, the correct leaf is still recoverable once the hierarchy enforces the correct parent path.
- If `acc_l2_ind_given_l1_correct` collapses while support stays high, the problem is not parent identification. The problem is that the global independent fine argmax is now choosing the wrong leaf across parent subtrees.

The most important comparison is not just `ind` versus `td`, but:

- unconditional fine accuracy versus conditional fine accuracy for the same decoder
- support before and after the switch
- whether the `ind` collapse remains after conditioning on correct parent

Useful patterns:

- High support, high `acc_l2_ind_given_l1_correct`, high `acc_l2_td_given_l1_correct`: healthy regime. Parent and leaf decisions are both stable.
- Low support, but high conditional accuracies: parent prediction is the bottleneck. Once the parent is right, the leaf is usually right too.
- High support, low `acc_l2_ind_given_l1_correct`, high `acc_l2_td_given_l1_correct`: classic HCC cross-parent competition failure. The parent is usually right, and the leaf is recoverable inside that parent, but the independent global leaf argmax is being hijacked by other parent subtrees.
- Low support and low conditional accuracies for both decoders: broader representation failure. The issue is not just the global leaf argmax.

A compact way to think about it:

- `support_l1_*_correct` asks "Did I enter the right family?"
- `acc_l2_*_given_l1_correct` asks "Once inside the right family, did I pick the right species/variant?"

That is exactly the CUB and Aircraft failure mode.

## Why `gt_parent_mass_pre_l2` Goes Up While `gt_parent_mass_post_l2` Goes Down

This is not a contradiction. The two metrics stop measuring the same thing once HCC turns on.

- `gt_parent_mass_pre_l2` is computed from raw fine softmax before projection.
- `gt_parent_mass_post_l2` is computed from the final projected probabilities after HCC.

Once HCC is active:

- The raw fine head can become sharper inside the GT family, so `pre` mass rises.
- But HCC then clamps the whole GT fine subtree to the parent-level budget produced by the middle head, so `post` mass can drop sharply.

This means the fine head and middle head are disagreeing more before projection.

The figure [parent_mass_reallocation.svg](figures/hcc_internal_insights_slides/parent_mass_reallocation.svg) shows this clearly.

## Why `gt_child_rank_within_parent_*` Barely Changes

The logs show that `gt_child_rank_within_parent_pre_l2` and `post_l2` are almost identical.

That matches the implementation:

- `_mass_renormalize` scales all children under the same parent by a common factor.
- A common per-parent scale preserves the order of siblings within that parent.
- The affine step before renormalization can perturb values, but in these runs the final sibling ranking barely moves.

So the main problem is not sibling re-ranking. The main problem is cross-parent competition after subtree budgets are enforced.

## Dataset-by-Dataset Findings

| Dataset | Fine per middle parent | Baseline `FPA_ind` | Step100 epoch 115 `FPA_ind` | Main outcome |
| --- | ---: | ---: | ---: | --- |
| CIFAR-100 | min=5 mean=5.00 max=5 | 72.75% | 74.21% | HCC mostly fixes inconsistency without rewriting many fine decisions |
| CUB-200 | min=1 mean=5.26 max=30 | 79.67% | 20.23% | Hard HCC severely breaks global fine argmax while TD remains strong |
| Aircraft | min=1 mean=1.43 max=8 | 68.44% | 54.71% | Same failure mode as CUB, but milder because family sizes are smaller overall |

The fan-out picture is in [taxonomy_fanout.svg](figures/hcc_internal_insights_slides/taxonomy_fanout.svg).

### CIFAR-100

What happens:

- The switch produces only a small rewrite: flip rate is 7.30% at epoch 115.
- `TICE_independent` improves from 8.40% at epoch 100 to 2.83% at epoch 115.
- `FPA_independent` improves from 72.78% at epoch 100 to 74.21% at epoch 115.
- `acc_l2_ind_given_l1_correct` improves from 85.94% at epoch 100 to 87.88% at epoch 115.

Why:

- CIFAR has perfectly uniform five-way middle nodes.
- The parent-budget rescaling does not strongly favor some branches over others.
- HCC removes cross-level inconsistency without substantially disrupting the fine competition.

### CUB-200

What happens:

- The collapse is immediate at the switch.
- `FPA_independent` goes from 79.01% at epoch 100 to 18.69% at epoch 101.
- `TICE_independent` goes from 5.92% at epoch 100 to 79.49% at epoch 101.
- Flip rate is 76.97% at epoch 115.
- `support_l1_ind_correct` stays high, around 94%.
- `acc_l2_ind_given_l1_correct` collapses from 84.05% at epoch 100 to 21.86% at epoch 115.
- `acc_l2_td_given_l1_correct` stays high at 85.88% at epoch 115.

Why:

- The parent is still usually correct.
- The correct leaf is still usually recoverable if the parent is enforced.
- The independent global leaf argmax is failing because HCC reweights parent subtrees, and CUB has very uneven family sizes, from 1 up to 30 species.
- Large families are penalized because their parent budget must be spread across many species, while small families can concentrate their budget into a few strong leaves.

### FGVC-Aircraft

What happens:

- The failure mode is the same as CUB, but less extreme.
- `FPA_independent` goes from 68.83% at epoch 100 to 50.22% at epoch 101, then ends at 54.71%.
- `TICE_independent` rises from 13.34% at epoch 100 to 39.31% at epoch 101, then ends at 34.43%.
- Flip rate is 38.45% at epoch 115.
- `support_l1_ind_correct` stays around 81%.
- `acc_l2_ind_given_l1_correct` falls from 86.04% at epoch 100 to 68.83% at epoch 115.
- `acc_l2_td_given_l1_correct` stays around 90.14% at epoch 115.

Why:

- Aircraft also has uneven fan-out.
- The average family is small, but the hierarchy is dominated by singleton families: 54 out of 70 middle nodes have exactly one leaf.
- Singletons or tiny families can preserve very strong leaf scores under HCC, while larger families still split their budget.
- That produces the same independent-decoding bias as CUB, just with a smaller collapse.

## Practical Interpretation of the Main HCC Metrics

Use this pattern when reading future logs:

- `proj_residual_after_l1` near zero means the projector is numerically enforcing the constraints correctly.
- `proj_flip_rate_level_2` tells you how invasive the projection is.
- `proj_gt_prob_delta_level_2` tells you whether the GT leaf gains or loses probability after projection.
- `gt_parent_mass_pre_l2` versus `gt_parent_mass_post_l2` tells you whether the fine head wants more GT-family mass than the parent head is willing to allocate.
- `acc_l2_ind_given_l1_correct` versus `acc_l2_td_given_l1_correct` tells you whether the failure remains after conditioning on correct parent, but read those together with `support_l1_*_correct` because the masks can differ.
- `tice_independent` tells you whether HCC is improving or worsening cross-level consistency under independent decoding.

Healthy pattern:

- Low flip rate.
- Lower `TICE_independent`.
- Stable or better `acc_l2_ind_given_l1_correct`.
- Small gap between `pre` and `post` parent mass.

Failure pattern:

- High flip rate.
- Higher `TICE_independent`.
- `support_l1_ind_correct` still high, but `acc_l2_ind_given_l1_correct` collapses.
- Large `pre` versus `post` parent-mass gap.

## Bottom Line

The current hard HCC behaves like a parent-budget clamp on the fine head.

That helps when the hierarchy is balanced, as in CIFAR-100.

That hurts when the hierarchy is uneven, as in CUB-200 and FGVC-Aircraft, because independent fine decoding makes all leaves compete globally even though HCC has reweighted them according to parent budgets. In those datasets, top-down decoding stays strong because the parent path is still mostly correct, but independent decoding becomes biased toward leaves from small or singleton parent subtrees.
